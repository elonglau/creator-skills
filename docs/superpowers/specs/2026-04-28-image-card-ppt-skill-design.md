# image-card-ppt 技能设计

日期：2026-04-28

## 目标

创建 `skills/image-card-ppt/SKILL.md` 的第一版文档。这个 skill 面向 AI agent，用于把小红书内容创作中的原始文稿转化为结构化信息卡片输出。

MVP 阶段的文档目标是先把未来实现前的工作流说清楚：agent 应该在什么场景下使用这个 skill，应该接收什么输入，应该如何把原始文稿转成固定 schema，后续脚本会产出哪些文件，以及当前阶段明确不做哪些能力。

## 读者

主要读者是 AI 编程或内容处理 agent。文档不应写成普通用户 README，而应写成 agent 可执行的工作协议。

面向人类使用者的安装、运行和配置说明可以在脚本与示例稳定后再补充。

## SKILL.md 结构

初始版 `SKILL.md` 应包含：

1. frontmatter：包含 `name: image-card-ppt` 和简洁 description。
2. 技能目标与适用场景。
3. 预期输入。
4. MVP 工作流。
5. 卡片内容固定 schema 草案。
6. 截图或其他图片素材的引用规则。
7. 模板风格配置概念。
8. 预期输出产物。
9. 质量检查要求。
10. MVP 非目标。
11. 后续扩展点。

## MVP 工作流

agent 工作流应描述为：

1. 接收用户提供的原始文稿。
2. 识别用户输入中可能包含的截图或其他图片素材，并记录素材路径、用途和适合放置的卡片位置。
3. 将原始文稿提取或改写为固定中间 schema。
4. 按 schema 拆分为一组有顺序的信息卡片，并为需要图片的卡片绑定素材引用。
5. 选择模板风格配置，例如设计风或科技风。
6. 使用 HTML 模板渲染每张卡片，正文区域需要按布局规则合理引用图片。
7. 使用本地 Python 脚本与 Playwright 将 HTML 卡片转为图片。
8. 返回生成的图片路径，并总结本次卡片序列。

第一版 `SKILL.md` 只需要描述这个流程，不需要包含可运行脚本。

## Schema 草案

文档应定义一个实用的 schema 草案，作为后续实现的默认契约：

- `title`：主题或封面标题。
- `subtitle`：可选的副标题。
- `audience`：目标读者。
- `tone`：文案与视觉语气。
- `canvas`：画布尺寸。默认使用小红书竖版信息卡尺寸 `1080x1440 px`，宽高比 `3:4`，也就是高宽比 `4:3`。
- `cards`：有顺序的卡片对象列表。
- `cards[].type`：卡片角色，例如 `cover`、`point`、`steps`、`quote` 或 `summary`。
- `cards[].headline`：卡片标题。
- `cards[].body`：卡片正文内容块。
- `cards[].media_refs`：当前卡片引用的图片素材 ID 列表。
- `cards[].layout_hint`：正文与图片的布局关系，例如上图下文、左右分栏、背景图或内嵌注释。
- `cards[].visual_hint`：可选的布局、配图或重点强调提示。
- `media_assets`：用户输入中的截图或图片素材列表，记录素材 ID、类型、路径、替代描述、用途和使用说明。
- `metadata`：原文摘要、模板名称与生成说明。

这个 schema 可在实现阶段调整，但 MVP skill 应把它作为默认数据契约。

## 图片素材引用

用户输入可能包含截图或其他图片字段。MVP 应把这些图片视为结构化素材，而不是纯附件。

agent 应判断图片的作用，例如证据截图、案例展示、产品界面、氛围图、封面主视觉或装饰素材。图片应先进入 `media_assets`，再由具体卡片通过 `media_refs` 引用。

HTML 正文部分引用图片时应有明确布局规则。常见规则包括上图下文、下图上文、左右分栏、背景图、局部放大或正文内嵌注释。若图片尺寸、比例或清晰度不适合当前卡片，agent 应在生成说明中标明，并建议裁剪、替换或调整布局。所有图文布局都应落在 `1080x1440 px` 的竖版画布内。

## 模板配置

MVP 应把模板描述为具名配置，而不是硬编码的一次性 HTML 文件。

每个模板风格后续应控制：

- 画布尺寸：MVP 默认 `1080x1440 px`，宽高比 `3:4`，按小红书竖版信息卡使用；不要误设为横版 `4:3`。
- 字体排版。
- 颜色。
- 间距。
- 装饰元素。
- 不同卡片类型的布局规则。
- 图片与正文组合规则。

初始文档应包含 `design` 和 `tech` 两个示例风格，因为它们已经出现在当前目标中。

## 输出产物

后续实现应产出：

- 规范化后的 schema JSON 文件。
- 用户输入图片的素材清单及其卡片引用关系。
- 每张卡片对应的 HTML 文件，或等价的可渲染 HTML 产物。
- 每张卡片通过 Playwright 渲染出的图片。
- 一份简短生成报告，包含卡片数量、模板风格和输出路径。

## 错误处理

当原始文稿过短、缺少明确主题，或与用户要求的卡片风格冲突时，skill 应要求 agent 停止并向用户澄清。

当用户提供图片但没有说明用途，且 agent 无法从上下文判断图片应放在哪张卡片时，也应先澄清。图片路径不可访问、图片内容无法识别，或图片比例明显不适合目标卡片时，应说明问题，不要伪造图片引用。

skill 应避免静默兜底。后续脚本渲染失败时，agent 应先根据脚本错误或浏览器错误定位根因，再修改模板或 schema。

## 测试要求

MVP 文档应声明后续实现至少需要覆盖：

- 从样例文稿生成 schema。
- 从包含图片素材的样例输入生成 `media_assets` 与 `media_refs`。
- 加载模板配置。
- 生成 HTML 渲染产物。
- 使用 Playwright 生成截图。

## 非目标

MVP 不承诺实现：

- 多平台发布。
- 自动上传小红书。
- AI 图片生成。
- 复杂设计系统。
- GUI 编辑器。
- 生产级模板市场能力。

这些能力可以在本地生成闭环稳定后作为后续工作。

## 验收标准

初始 `SKILL.md` 满足以下条件即可接受：

- 明确面向 AI agent 执行。
- 文档说明从原始文稿到 schema、HTML、图片的流程。
- 提到 Python 与 Playwright 的本地渲染方向，但不要求当前实现脚本。
- 包含 schema 草案、图片素材引用规则和模板配置概念。
- 保持 MVP 范围收敛，不把未来能力描述成当前能力。
