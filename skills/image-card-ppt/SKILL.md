# image-card-ppt

## 目标

当用户提供小红书内容创作相关的原始文稿，并希望产出一组适合发布或排版的信息卡片时，使用本技能。

本技能的核心目标是指导 agent 将原始文稿转化为结构化卡片数据，再交给后续本地 Python 与 Playwright 渲染流程，把 HTML 模板输出为图片。

当前阶段是 MVP 工作协议。它定义输入、schema、模板配置、输出与质量检查，不包含可运行脚本。

## 适用场景

在以下情况使用本技能：

- 用户提供一段原始文稿，希望转成小红书信息卡片。
- 用户希望把内容拆成封面、观点、步骤、引用、总结等多张卡片。
- 用户要求使用固定 schema 管理卡片内容。
- 用户希望后续通过 HTML 模板生成不同视觉风格的卡片图，例如设计风或科技风。
- 用户希望本地脚本使用 Python 与 Playwright 将 HTML 渲染为图片。

不要在以下情况使用本技能：

- 用户只需要普通文案润色，不需要卡片结构。
- 用户要求直接上传或发布到小红书。
- 用户要求生成复杂 GUI 编辑器。
- 用户要求使用 AI 生成配图，而不是基于 HTML 模板渲染卡片。

## 输入

优先从用户请求中识别以下输入：

- `raw_text`：原始文稿，必需。
- `style`：模板风格，可选，默认使用 `design`。
- `card_count`：期望卡片数量，可选，MVP 中可根据内容自动建议。
- `audience`：目标读者，可选。
- `tone`：文案与视觉语气，可选。
- `constraints`：用户指定的标题、禁用表达、必须保留的信息或输出格式要求。

如果原始文稿过短、主题不明确，或用户要求的风格与内容明显冲突，先向用户澄清，不要静默猜测。

## MVP 工作流

执行任务时按以下顺序处理：

1. 阅读用户提供的原始文稿，识别主题、受众、核心观点和可拆分的信息层级。
2. 将原始文稿提取或改写为固定 schema。
3. 将 schema 中的内容拆分为有顺序的信息卡片。
4. 根据用户指定或默认规则选择模板风格配置。
5. 将每张卡片映射到 HTML 模板所需的数据。
6. 后续实现中，调用本地 Python 脚本生成 HTML，并使用 Playwright 截图输出图片。
7. 返回 schema、卡片序列摘要、模板风格和生成产物路径。

当前没有脚本时，只产出 schema 与卡片规划，不声称已经生成 HTML 或图片。

## 固定 Schema

默认使用以下结构作为卡片内容契约：

```json
{
  "title": "主题或封面标题",
  "subtitle": "可选副标题",
  "audience": "目标读者",
  "tone": "文案与视觉语气",
  "cards": [
    {
      "type": "cover",
      "headline": "卡片标题",
      "body": ["正文内容块"],
      "visual_hint": "可选的布局、配图或重点强调提示"
    }
  ],
  "metadata": {
    "source_summary": "原文摘要",
    "template": "design",
    "generation_notes": ["生成说明"]
  }
}
```

字段说明：

- `title`：主题或封面标题。
- `subtitle`：副标题，可为空。
- `audience`：目标读者。
- `tone`：文案与视觉语气。
- `cards`：有顺序的卡片对象列表。
- `cards[].type`：卡片角色，建议从 `cover`、`point`、`steps`、`quote`、`summary` 中选择。
- `cards[].headline`：卡片标题。
- `cards[].body`：短正文内容块，每项应适合放入单张卡片。
- `cards[].visual_hint`：可选视觉提示，用于指导模板布局或强调信息。
- `metadata.source_summary`：对原始文稿的简短摘要。
- `metadata.template`：使用的模板风格名称。
- `metadata.generation_notes`：生成过程中的重要说明。

## 模板风格配置

模板应被视为具名配置，而不是一次性硬编码 HTML。

MVP 预期至少支持以下风格概念：

- `design`：偏设计感、排版感，适合方法论、审美、品牌、内容创作主题。
- `tech`：偏科技感、理性结构，适合 AI、工具、效率、技术解释主题。

每个模板风格后续应控制：

- 画布尺寸。
- 字体排版。
- 颜色。
- 间距。
- 装饰元素。
- 不同卡片类型的布局规则。

在用户提供参考图后，先提炼可配置的视觉规则，再修改模板配置。不要把单张参考图直接写死为唯一布局。

## 输出

完整实现后，技能应产出：

- 规范化后的 schema JSON 文件。
- 每张卡片对应的 HTML 文件，或等价可渲染 HTML 产物。
- 每张卡片通过 Playwright 渲染出的图片。
- 一份生成报告，包含卡片数量、模板风格和输出路径。

MVP 文档阶段或脚本缺失时，输出应限制为：

- schema 草案。
- 卡片序列规划。
- 推荐模板风格。
- 后续脚本执行计划。

## 质量检查

交付前检查：

- schema 是否包含 `title`、`cards` 和 `metadata`。
- 每张卡片是否只有一个清晰主旨。
- 卡片顺序是否符合小红书阅读节奏。
- 正文是否适合卡片展示，避免长段落堆叠。
- 模板风格是否与内容主题匹配。
- 如果已经有脚本实现，确认 HTML 与图片文件确实生成。

## 错误处理

遇到以下情况时先澄清：

- 原始文稿无法判断主题。
- 用户要求的卡片数量与内容体量明显不匹配。
- 用户同时要求多个互相冲突的风格。
- 用户要求当前 MVP 未实现的能力，例如自动发布或 GUI 编辑。

后续脚本渲染失败时，先定位根因。不要通过静默切换模板、跳过失败卡片或伪造输出路径来掩盖问题。

## 测试要求

后续实现脚本后，至少补充以下最小测试：

- 从样例文稿生成 schema。
- 加载模板配置。
- 生成 HTML 渲染产物。
- 使用 Playwright 生成截图。

新增功能必须配套最小范围测试。

## 非目标

MVP 不包含：

- 自动发布到小红书。
- 多平台发布管理。
- AI 图片生成。
- GUI 编辑器。
- 复杂设计系统。
- 生产级模板市场。

这些能力只能在本地 schema 到 HTML 到图片的生成闭环稳定后再评估。
