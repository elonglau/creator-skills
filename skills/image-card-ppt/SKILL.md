# image-card-ppt

## 目标

当用户提供小红书内容创作相关的原始文稿，并希望产出一组适合发布或排版的信息卡片时，使用本技能。

本技能的核心目标是指导 agent 将原始文稿转化为结构化卡片数据，再交给后续本地 Python 与 Playwright 渲染流程，把 HTML 模板输出为图片。

当前阶段是 MVP 工作协议。它定义输入、schema、模板配置、输出与质量检查，不包含可运行脚本。

## 适用场景

在以下情况使用本技能：

- 用户提供一段原始文稿，希望转成小红书信息卡片。
- 用户希望把内容拆成封面、观点、步骤、引用、总结等多张卡片。
- 用户要求使用固定 schema 管理卡片内容。
- 用户希望后续通过 HTML 模板生成不同视觉风格的卡片图，例如设计风或科技风。
- 用户希望本地脚本使用 Python 与 Playwright 将 HTML 渲染为图片。

不要在以下情况使用本技能：

- 用户只需要普通文案润色，不需要卡片结构。
- 用户要求直接上传或发布到小红书。
- 用户要求生成复杂 GUI 编辑器。
- 用户要求使用 AI 生成配图，而不是基于 HTML 模板渲染卡片。

## 输入

优先从用户请求中识别以下输入：

- `raw_text`：原始文稿，必需。
- `style`：模板风格，可选，默认使用 `design`。
- `card_count`：期望卡片数量，可选，MVP 中可根据内容自动建议。
- `audience`：目标读者，可选。
- `tone`：文案与视觉语气，可选。
- `media_assets`：截图或其他图片素材，可选。每个素材应尽量包含路径、用途说明、来源说明和用户希望关联的正文位置。
- `constraints`：用户指定的标题、禁用表达、必须保留的信息或输出格式要求。

如果原始文稿过短、主题不明确，或用户要求的风格与内容明显冲突，先向用户澄清，不要静默猜测。

如果用户输入包含截图或其他图片，先判断图片在内容中的作用：证据截图、案例展示、产品界面、氛围图、封面主视觉或装饰素材。不要把图片当作纯附件忽略。

## MVP 工作流

执行任务时按以下顺序处理：

1. 阅读用户提供的原始文稿，识别主题、受众、核心观点和可拆分的信息层级。
2. 识别截图或其他图片素材，记录素材路径、用途和适合放置的卡片位置。
3. 将原始文稿提取或改写为固定 schema。
4. 将 schema 中的内容拆分为有顺序的信息卡片，并为需要图片的卡片绑定素材引用。
5. 根据用户指定或默认规则选择模板风格配置。
6. 将每张卡片映射到 HTML 模板所需的数据，包括正文、图片引用和布局提示。
7. 后续实现中，调用本地 Python 脚本生成 HTML，并使用 Playwright 截图输出图片。
8. 返回 schema、卡片序列摘要、模板风格和生成产物路径。

当前没有脚本时，只产出 schema 与卡片规划，不声称已经生成 HTML 或图片。

## 固定 Schema

默认使用以下结构作为卡片内容契约：

```json
{
  "title": "主题或封面标题",
  "subtitle": "可选副标题",
  "audience": "目标读者",
  "tone": "文案与视觉语气",
  "canvas": {
    "width": 1080,
    "height": 1440,
    "ratio": "3:4"
  },
  "cards": [
    {
      "type": "cover",
      "variant": "cover",
      "headline": "卡片标题",
      "body": ["正文内容块"],
      "media_refs": ["asset_001"],
      "layout_hint": "正文与图片的布局关系",
      "visual_hint": "可选的布局、配图或重点强调提示"
    }
  ],
  "media_assets": [
    {
      "id": "asset_001",
      "type": "screenshot",
      "src": "图片路径或用户输入中的图片引用",
      "alt": "图片内容描述",
      "role": "evidence",
      "notes": "使用说明"
    }
  ],
  "metadata": {
    "source_summary": "原文摘要",
    "template": "design",
    "generation_notes": ["生成说明"]
  }
}
```

字段说明：

- `title`：主题或封面标题。
- `subtitle`：副标题，可为空。
- `audience`：目标读者。
- `tone`：文案与视觉语气。
- `canvas`：画布尺寸。默认使用小红书竖版信息卡尺寸 `1080x1440 px`，宽高比 `3:4`，也就是高宽比 `4:3`。
- `cards`：有顺序的卡片对象列表。
- `cards[].type`：卡片角色，建议从 `cover`、`point`、`steps`、`quote`、`summary` 中选择。
- `cards[].variant`：模板排版变体，MVP 必须支持 `cover`、`image_page`、`text_page`、`summary`。封面与内页排版不同，不能只使用同一套正文布局。
- `cards[].headline`：卡片标题。
- `cards[].body`：短正文内容块，每项应适合放入单张卡片。
- `cards[].media_refs`：当前卡片引用的图片素材 ID 列表，可为空。
- `cards[].layout_hint`：正文与图片的布局关系，例如 `image_top`、`image_bottom`、`split`、`background`、`inline_callout`。
- `cards[].visual_hint`：可选视觉提示，用于指导模板布局或强调信息。
- `media_assets`：用户输入中的截图或图片素材列表。
- `media_assets[].id`：素材唯一 ID，供卡片引用。
- `media_assets[].type`：素材类型，例如 `screenshot`、`photo`、`reference`、`illustration`。
- `media_assets[].src`：素材路径或输入引用。
- `media_assets[].alt`：图片内容描述，用于可读性与调试。
- `media_assets[].role`：图片在卡片中的作用，例如 `evidence`、`example`、`hero`、`decoration`。
- `media_assets[].notes`：素材使用说明或限制。
- `metadata.source_summary`：对原始文稿的简短摘要。
- `metadata.template`：使用的模板风格名称。
- `metadata.generation_notes`：生成过程中的重要说明。

## 模板风格配置

模板应被视为具名配置，而不是一次性硬编码 HTML。

MVP 预期至少支持以下风格概念：

- `design`：偏设计感、排版感，适合方法论、审美、品牌、内容创作主题。
- `tech`：偏科技感、理性结构，适合 AI、工具、效率、技术解释主题。

每个模板风格后续应控制：

- 画布尺寸：MVP 默认 `1080x1440 px`，宽高比 `3:4`，按小红书竖版信息卡使用；不要误设为横版 `4:3`。
- 字体排版。
- 颜色。
- 间距。
- 装饰元素。
- 不同卡片类型的布局规则。
- 图片与正文组合规则。

当前 `design` 风格模板路径：

- `templates/design.html`
- `templates/design.config.json`
- `templates/design-v2.html`
- `templates/design-v2.config.json`

`design` 风格基于浅灰背景、黑色大标题、蓝色强调色、细分隔线、顶部元信息、右上胶囊标签、居中图片展示框和底部页脚信息构成。MVP 必须覆盖封面卡、图文内页、纯文字内页和总结页。

`design-v2` 是推荐的新设计版本，面向更高级的浅色玻璃质感：背景使用克制的浅色渐变、低透明网格和边缘微光来增加质感；正文使用高对比深色；内容区、要点区、图片区使用半透明卡片、轻边框和微光阴影；整体保留大留白，优先保证阅读清晰度。

`design` 风格的排版变体：

- `cover`：封面排版。保留左上品牌、右上主题提示、蓝色引导线、大标题、短摘要和底部数据栏。
- `image_page`：图文内页。使用左上页码、右上胶囊标签、标题、说明文字、居中图片展示框、图片说明条和页脚。
- `text_page`：纯文字内页。用于观点、步骤、引用等无图卡片，使用更大的正文要点和蓝色方块标记。
- `summary`：总结页。用于收束观点或行动号召，保留封面式留白，但不显示底部数据栏。

`design` 风格默认个人 IP 配置为 `飞柳OnMyWay`。后续脚本应优先读取 `templates/design.config.json`，允许用户覆盖 `brand.name` 和 `brand.subtitle`，但没有显式覆盖时必须使用默认账号。

HTML 正文引用图片时应遵守：

- 通过 `media_refs` 引用 `media_assets`，不要在正文里散落不可追踪的图片路径。
- 截图类素材应优先用于证明、对比、步骤说明或案例展示，不要只作为装饰。
- 图片进入正文布局时必须有明确空间规则，例如上图下文、左右分栏、背景图、局部放大或内嵌注释。
- 如果图片尺寸、比例或清晰度不适合当前卡片，应在 `generation_notes` 中说明，并建议裁剪或替换。
- 所有正文与图片布局都必须落在 `1080x1440 px` 的竖版画布内，避免内容超出安全边界。

在用户提供参考图后，先提炼可配置的视觉规则，再修改模板配置。不要把单张参考图直接写死为唯一布局。

## 输出

完整实现后，技能应产出：

- 规范化后的 schema JSON 文件。
- 用户输入图片的素材清单及其卡片引用关系。
- 每张卡片对应的 HTML 文件，或等价可渲染 HTML 产物。
- 每张卡片通过 Playwright 渲染出的图片。
- 一份生成报告，包含卡片数量、模板风格和输出路径。

MVP 文档阶段或脚本缺失时，输出应限制为：

- schema 草案。
- 卡片序列规划。
- 图片素材与卡片的引用规划。
- 推荐模板风格。
- 后续脚本执行计划。

## 质量检查

交付前检查：

- schema 是否包含 `title`、`cards` 和 `metadata`。
- schema 是否包含默认画布尺寸 `1080x1440 px`，或明确说明用户覆盖后的尺寸。
- 每张卡片是否只有一个清晰主旨。
- 每张卡片是否选择了合适的 `variant`，且封面、图文内页、纯文字内页、总结页的排版差异明确。
- 卡片顺序是否符合小红书阅读节奏。
- 正文是否适合卡片展示，避免长段落堆叠。
- 用户输入的截图或图片是否被合理引用，而不是丢失或无意义装饰。
- 图文布局是否有明确规则，避免正文遮挡图片或图片挤压正文。
- 模板风格是否与内容主题匹配。
- 如果已经有脚本实现，确认 HTML 与图片文件确实生成。

## 错误处理

遇到以下情况时先澄清：

- 原始文稿无法判断主题。
- 用户要求的卡片数量与内容体量明显不匹配。
- 用户同时要求多个互相冲突的风格。
- 用户提供了图片但没有说明用途，且无法从上下文判断图片应放在哪张卡片。
- 图片路径不可访问、图片内容无法识别，或图片比例明显不适合目标卡片。
- 用户要求当前 MVP 未实现的能力，例如自动发布或 GUI 编辑。

后续脚本渲染失败时，先定位根因。不要通过静默切换模板、跳过失败卡片或伪造输出路径来掩盖问题。

## 测试要求

后续实现脚本后，至少补充以下最小测试：

- 从样例文稿生成 schema。
- 从包含图片素材的样例输入生成 `media_assets` 与 `media_refs`。
- 加载模板配置。
- 生成 HTML 渲染产物。
- 分别渲染 `cover`、`image_page`、`text_page`、`summary` 四类 MVP 排版。
- 使用 Playwright 生成截图。

新增功能必须配套最小范围测试。

## 非目标

MVP 不包含：

- 自动发布到小红书。
- 多平台发布管理。
- AI 图片生成。
- GUI 编辑器。
- 复杂设计系统。
- 生产级模板市场。

这些能力只能在本地 schema 到 HTML 到图片的生成闭环稳定后再评估。
